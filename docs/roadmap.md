# ロードマップ

タスクの進捗状態。着手前に「そもそも対応するか」を決めるものは判断待ちに置く。

## 判断待ち

対応するかどうかの判断そのものがタスク。やると決まったら着手予定へ移す。

### Twitch のコメント読み上げ

設定画面のモックアップ（`docs/references/jpnkn-vox-settings-inline.html`）には
jpnkn・ツイキャスと並んで Twitch があるが、ツイキャス対応の時点では入れないと判断した。

やる場合は `SourceType` に足して `CommentConnector` を実装する。
IRC over WebSocket（`wss://irc-ws.chat.twitch.tv`）にアノニマスで繋げば認証は要らない。

## 見送り

### 自アプリが前面のときはオーバーレイを出さない（2026-08-12 に見送り）

前面判定はなく、サービス稼働中は常に表示される。
そのため設定画面を開くとオーバーレイが自前の UI（テスト再生ボタンなど）に重なる。
これを出し分ける案。

**見送りの理由**: 現状のままでよいとの判断。

**留意点**: TopAppBar の「稼働中／停止中」は `isServiceRunning`（サービスの起動状態）であって
MQTT の接続状態ではない。アプリ内に接続状態の常時表示はないため、
オーバーレイを隠すと接続状態を見る手段がなくなる。

### フォアグラウンド通知のテキストを動的にする（2026-08-12 に見送り）

`JpnknVoxService.createNotification()` は
`setContentTitle("JPNKN Vox")` / `setContentText("JPNKN 接続中")` の固定文字列で、
接続状態とも板 ID とも連動しない（切断中も「接続中」と出続ける）。
これを状態に応じて更新する案。

**見送りの理由**: 現状のままでよいとの判断。

**留意点**: 「常駐状態は通知に出ているのだからオーバーレイのステータス表示は消せる」
という論法は、この対応が前提になる。固定文言のままなので、その前提では設計しないこと。

### 切断表示のデバウンス（2026-08-12 に見送り）

切断が数秒続いてから色を変える案。切断→即再接続を繰り返す回線で
アプリ名の色が緑↔黄に点滅するのを抑える目的だった。

**見送りの理由**: IRL 配信では電波状況そのものが行動につながる情報のため。
点滅が頻発するなら場所を変える・歩きを止めるといった判断ができる。
デバウンスはその情報を握りつぶすことになる。

## 完了

- ツイキャスのコメント読み上げに対応し、設定画面を複数の「コメント取得先」を登録できるリストに作り替えた
- オーバーレイの本文を受信時ではなく読み上げ開始時に更新し、読み上げの遅れと表示のずれをなくした
- 設定画面の「文字の色」を「文字の大きさ」（4 段階）に置き換え、オーバーレイの上下の余白と文字色を調整した
- オーバーレイの文字を縁取り＋影＋太字にし、レイアウトを調整（`7dd1ca4`）
- 設定画面でオーバーレイの文字色を指定できるようにした（`1d2bd23`）
